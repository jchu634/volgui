# Network investigation

## Caller workflow

Choose Network investigation and correlation in New analysis, or Analyze network in Network. The draft queues available socket, process, command history and handle inventories before the native parser. The native job waits for preceding engine work, correlates their saved records and stores ordinary immutable finding records and hashed output through the existing case lifecycle.

`Graph::load(store, query, epoch, token)` builds IP and endpoint membership off the UI thread. `Selection::Address(ip)` includes either side at every port; `Selection::Endpoint(endpoint)` requires address and port together on the same side, including an unknown port. The UI opens original records with `load_record` or `show_record` and resolves process links through the existing PID ambiguity checks.

## Storage and rendering

SQLite remains authoritative. `ResultStore::network_ids` returns every run/row occurrence in the selected scope. It bypasses the general browser's representative deduplication. The graph uses raw records so conflicting entity enrichment cannot invent a socket owner or overwrite an endpoint.

The graph shows one focus IP or all source IPs on a continuously scrolling canvas. Every peer has a position; controls and links are created only near the viewport. Each peer shows up to twelve port pairs, with an explicit overflow count and access to all entries through the sidebar. The sidebar pages through all occurrences, forty at a time. Graph, table and sidebar share search, protocol, state and noise filters. The sortable native table virtualizes rows, retains each source occurrence and exposes endpoint, process, finding and provenance columns. The graph focus applies only to graph edges, so switching to Table lists all filtered records. Text-only references have separate nodes without invented links to the focus host. Explicit drive-command credentials and previously saved configuration candidates sort before other endpoint records. Bottom details retain bookmarks, raw JSON and run diagnostics. Source bytes opens the acquisition at the saved match offset, with context offset retained separately. Back retains the endpoint, filters, pages and graph scroll position.

The first alternative was a persisted, versioned endpoint projection with SQL indexes. That supports larger cases with less memory, but adds migrations and synchronization for a derived view. The second was standalone indexed analysis bundles, which duplicated case ownership. This implementation uses an in-memory projection built from SQLite occurrences. It accepts memory proportional to the scoped network records while bounding rendered controls to the canvas viewport and forty sidebar cards. Search text and sidebar priority are prepared during background loading. Overview and sidebar membership are cached until their inputs change, so scrolling does not rescan and sort the scope. No second persistent data store is introduced.

## Evidence rules

Sockets and recovered command text remain distinct. The parser reads completed source runs preceding its queued job and records the exact source run, row and field, plus parser version and evidence fingerprint. It supports cancellation and reports a 20,000-finding limit and unavailable inventories. It extracts credentials only from explicit net use commands, excludes password prompts and scopes credentials to the specific command and share. It does not inspect unrelated username/password text or resolve share hostnames without separate evidence.

Parser version network-v3-configurations owns a bounded acquisition scan for structurally validated legacy Meterpreter TCP configurations. It validates the 48-byte session, UTF-16 transport URL padding, exit function, UUID and timeouts. Candidates remain unattributed and do not prove execution or a connection. The scanner retains preceding and following bytes across chunk boundaries, supports cancellation, stops at 2,000 configurations and reports coverage. Credentials and ordinary command text still come only from collected records. Global string search and Process Memory remain separate general recovery tools. Evidence-wide Network also loads historical Meterpreter findings from completed download reports, retaining the original source row and offsets. The download presentation excludes those rows without rewriting stored evidence.

## Verification

`tests/network.rs` covers exact endpoint pairing, IPv6 scopes, wildcard addresses, zero and missing ports, repeated observations across runs, stale workers, persistence, chooser prerequisites, queue barriers, quoted credentials, prompt markers, chained-command credential scoping, and source provenance. Regressions verify that network-shaped strings in raw acquisition bytes produce no findings and unrelated credentials in collected records are ignored, while credentials in an explicit network drive command retain their source run and row.

`examples/validate_network.rs` runs the same chooser queue and record correlation on a capture and exports network.csv into a new case. The acquisition and any existing case stay unchanged.

## Noise filters and view design

`Filter { hide_system, hide_noise, .. }` is the single matching policy for both views and the sidebar. `Graph::overview` caches matching occurrence indices, available addresses and graph edges. `NetworkTable` consumes those indices through the existing native DataTable, sorting numeric PID/port columns as numbers. It instantiates visible cells only. Protocol, state and search apply to findings as well as sockets; noise heuristics exempt all analysis findings. System classification uses common Windows process basenames, not a claim that a process is safe. Endpoint noise covers loopback, IPv4-mapped loopback, unspecified or wildcard endpoints, port zero and missing remote endpoints. Unknown owners and unknown ports do not imply noise. Filters start enabled in the UI and survive Back navigation. The focus picker uses filtered addresses and falls back to a visible local address when the previous focus is hidden.

Considered adapting the general result table by replacing its SQLite IDs after each filter change. That would couple network occurrence membership to the deduplicated result browser and overwrite the browser's search state. A dedicated DataTable delegate reuses virtualization, resizing and row selection while keeping membership in the network projection. Compared a general raw-text scanner with a configuration-only scanner. The latter keeps arbitrary acquisition text and credentials out of the network report while retaining the requested validated payload evidence. No new persistence or schema is needed. The architect skill's referenced how/arena tools are unavailable in this session; these alternatives were compared locally.

The download action row wraps within its content pane. Its width and minimum-width constraints prevent controls from painting over the content sidebar.

The final verification passed 102 selected library, network, download, result-store, entity and analysis-queue tests using `cargo test --no-default-features --lib --test network --test downloads --test results --test entities --test analyses --locked`. `cargo check --all-targets --locked` and formatting checks also passed. The native review build used the seeded case with 10,000 socket occurrences and one historical payload finding. UI checks verified independent noise counts, numeric port sorting, payload search, stable row selection, source bytes at offset zero, and wrapped download controls beside the content sidebar. The user's running executable was kept open; the review executable is built separately under `target/debug/volgui-network-review.exe`.

## Continuous canvas and evidence recovery

The toolbar has a filter row with Analyze network anchored at the right, followed by a graph/table and IP-navigation row. The picker uses 190px for IPv4 and 390px for IPv6. Its current IP is checked and highlighted, all entries are reachable through a scrollable menu, and Previous/Next use checked bounds without cycling. All source IPs preserves each source/peer pair, while text-only findings remain separate from observed edges. Scrolling creates controls within the viewport plus an overscan margin. Source nodes stay visible within their source section. The same graph scroll handle supports wheel scrolling and scrollbar dragging; peer paging is removed.

Interesting Traffic combines recovered analysis findings with SMB and common remote administration endpoints, including SSH, Telnet, RDP and WinRM. This identifies records worth inspecting, not malicious activity. Other filters still apply. The button queues native recovery when the current parser has not completed for the evidence, reuses a queued/running job, and retries interrupted or older parsers. A completed network job now refreshes an evidence-wide Network scope even when its run was not in the previously displayed scope.

A4-A1 investigation found one interrupted network job, no completed download investigation and no stored Meterpreter rows. A read-only reparse with `cargo run --no-default-features --example reparse_network -- <case-directory> <output-directory>` recovered two validated configurations for 10.73.53.11:5059 at configuration offsets 562862716 and 1392834952. Outputs are under `target/verification/network-a4-a1`; the source case and capture were not changed. Regression tests cover interrupted/current parser reuse, Interesting Traffic membership, bounded IP navigation and all-source endpoint pairing.

Final checks for the continuous canvas passed 67 selected library, network and download tests, all-target compilation, formatting and `cargo clippy --all-targets --locked -- -D warnings`. Native checks used a 10,043-entry fixture with 243 peer groups: Interesting Traffic queued and saved one missing configuration, refreshed the open view, and exposed its source evidence. IP highlighting, fixed IPv6 width across long and short addresses, disabled navigation at both boundaries, all-source rendering, wheel scrolling, dragging the scrollbar to the final source, and searching after scrolling were verified. The updated executable is `target/debug/volgui-network-canvas-review.exe`.
